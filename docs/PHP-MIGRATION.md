# برنامهٔ انتقال تدریجی منطق‌های اختصاصی از کد PHP

سامانهٔ جدید جایگزین کامل کد PHP نمی‌شود بلکه **مدول‌به‌مدول** منطق‌های اختصاصی (وب‌سرویس سها و پیامک واقعی) را جذب می‌کند. زیرساخت هر دو در نسخهٔ ۵.۱ آماده است و فقط «منطق دامنه» باید از PHP منتقل شود.

## معماری انتقال

```
کد PHP فعلی                     سامانهٔ جدید (Next.js)
──────────────                 ─────────────────────────────────
کرون جاب ارسال پیامک    ───▶   src/lib/sms/index.ts  → dispatchQueue()
کلاس/تابع اتصال سها     ───▶   src/lib/soha/client.ts → SohaClient.request()
توابع نگاشت فیلدها      ───▶   src/lib/soha/sync.ts   → mapSoha* (TODOها)
صف/لاگ عملیات           ───▶   جدول SyncLogs + پنل «یکپارچه‌سازی‌ها»
```

هر دو ماژول از طریق API زیر قابل اجرا هستند و هر اجرا در پنل «یکپارچه‌سازی‌ها» ثبت می‌شود:

- `POST /api/integrations/run` با `{ "action": "sms-dispatch", "limit": 200, "retry": true }`
- `POST /api/integrations/run` با `{ "action": "soha-sync", "entity": "Patients|Referrals", "direction": "IN|OUT" }`

| # | مورد | مبدأ (PHP) | مقصد (TS) | وضعیت |
|---|---|---|---|---|

| ۲ | نرمال‌سازی شماره موبایل | تابع PHP مربوطه | `normalizeMobile()` | ✅ بازنویسی شد |
| ۳ | ارائه‌دهندهٔ پنل سها | فایل ارسال PHP | `sohaProvider()` | ⬜ آدرس/پارامترهای واقعی پنل را تطبیق دهید |
| ۴ | ارائه‌دهندهٔ کاوه‌نگار / SMS.ir / ملی پیامک | — | `providers.ts` | ✅ آماده (کافیست کلید بدهید) |
| ۵ | قالب‌های پیامک (کد تأیید، یادآوری جلسه و...) | فایل‌های قالب PHP | «پیام‌ها» / مناسبت‌ها | ⬜ منتقل نشده |
| ۶ | اجرای خودکار دوره‌ای | کرون لینوکس | Task Scheduler ویندوز | ✅ دستور آماده در DEPLOY-MYSQL.md |

## چک‌لیست انتقال — وب‌سرویس سها

| # | مورد | مبدأ (PHP) | مقصد (TS) | وضعیت |
|---|---|---|---|---|
| ۱ | پیکربندی (آدرس، احراز هویت، کد مرکز) | فایل کانفیگ PHP | Settings (`soha.*`) + پنل | ✅ انجام شد |
| ۲ | کلاینت HTTP با تلاش مجدد و مهلت زمانی | کلاس PHP | `SohaClient` | ✅ بازنویسی شد |
| ۳ | دریافت بیماران | متد PHP | `syncPatientsFromSoha()` | ⬜ مسیر `/patients` و نگاشت فیلدها را از PHP تطبیق دهید |
| ۴ | دریافت ارجاعات | متد PHP | `syncReferralsFromSoha()` | ⬜ مسیر `/referrals` را تطبیق دهید؛ نگاشت کد استان (TODO در فایل) |
| ۵ | اعلام وضعیت ارجاع به سها | متد PHP | `pushReferralsToSoha()` | ⬜ سیاست «کدام ارجاع‌ها و چه زمانی» از PHP منتقل شود |
| ۶ | همگام‌سازی خدمات | متد PHP | `runSohaSync("Services")` | ⬜ پیاده‌سازی نشده — TODO در فایل |
| ۷ | احراز هویت SOAP (در صورت استفاده) | WSDL/SoapClient | `SohaClient` (REST) | ⬜ اگر سها فقط SOAP دارد، لایهٔ SOAP اضافه شود |

> 📌 **روش کار:** هنگام انتقال هر مورد، فایل PHP مربوطه را باز کنید، منطق را در متد علامت‌گذاری‌شده با `TODO(انتقال از PHP)` جایگزین کنید و وضعیت ردیف جدول بالا را به ✅ تغییر دهید. بقیهٔ سامانه از این تغییرات بی‌اطلاع است؛ قراردادها (DTOها) ثابت می‌مانند.

## نمونهٔ انتقال یک متد (الگو)

```ts
// src/lib/soha/sync.ts
const res = await client.request<any>("GET", "/patients", {
  centerCode: cfg.centerCode,
  updatedSince: cursor,
  take: opts.limit ?? SYNC_PAGE_SIZE,
});
// TODO(انتقال از PHP): اگر فیلدهای سها متفاوت‌اند فقط همین نگاشت را تغییر دهید
const items: SohaPatient[] = Array.isArray(res) ? res : (res?.items ?? res?.data ?? []);
```

## محیط آزمون

- تا قبل از تنظیم `soha.baseUrl`، هر همگام‌سازی با پیام شفاف در پنل و جدول SyncLogs «ناموفق» ثبت می‌شود و سامانه آسیب نمی‌بیند.
- تا قبل از فعال‌سازی `sms.enabled`، پیامک‌ها فقط در صف می‌مانند (هیچ پیام واقعی ارسال نمی‌شود).
- سرویس‌دهندهٔ «شبیه‌ساز (تست)» برای آزمایش کامل جریان بدون هزینهٔ پیامک در دسترس است.
